# 꼬마런닝 1.0 완성본 제작 계획

2026-11-28 · 저장소 `duafyd/kkoma_learning` · 진행 브랜치 `prototype/worksheet` · 실행 기준 [Godot 0.6 첫 화면](preview/play-menu.jpg)

## 완성본을 쓰는 모습

보호자가 갤럭시탭에 설치해 만 2·3·4·5세 중 아이의 연령을 한 번 고른다. 아이는 첫 화면에서 한글·영어·숫자를 독립적으로 고르거나 과일 가게 문을 열어 여러 과목의 주문을 함께 해결한다. 1.0에서는 빵집 주문도 독립 가게 놀이로 만난다. 한 판이 끝나면 자기가 포장한 물건과 쓴 이름표가 진열된다. 다음 날에는 최근과 다른 주문을 만나고, 중간에 그만둔 판은 이어갈 수 있다. 보호자는 아이가 혼자 해 본 것과 도움을 받아 해 본 것을 확인할 수 있다.

| 제작 기준 | 1.0에 담을 경험 |
| --- | --- |
| 기기·언어 | 갤럭시탭 가로, 손가락 한 개, 오프라인 첫 실행. 한국어 UI에 영어 학습 대사를 넣는다. 현재 Godot 4.7.2와 arm64 Android 경로를 이어 쓴다. |
| 화면·소리 | 승인한 2D 모모, 맑은 중간 채도, 간결한 가게 배경과 동적인 표정·소품. 둥근 황갈색 한국 배. 첫 실행은 음성과 효과음 켜짐이며 이후 사용자의 선택을 기억한다. 현재 A 음성은 교체 가능한 대사 ID로 관리한다. |
| 콘텐츠 | 과일 가게·빵집 각각 네 연령 × 다섯 영역 × 두 기본 주문. 한글·영어·수학·관찰·규칙의 대사와 정답은 [80개 주문 원고](ORDER_CATALOG.md)에 있다. |

## 제작 순서와 작업 장부

현재 완료 지점은 **기획 원고와 0.6 독립 놀이 진입**이다. 다음 개발은 아래 1단계에서 시작한다. 각 단계는 정상 진입점에서 아이가 실제로 쓸 수 있는 단위로 합친다. 개발 중에는 소스와 검증 결과를 브랜치에 남기고, 기기 검토나 인도가 필요한 지점에서 설치본을 갱신한다.

| 순서·상태 | 묶어서 구현할 일 | 이 단계를 끝냈다고 할 수 있는 조건 |
| --- | --- | --- |
| **1 · 다음 작업** 두 가게와 연령별 공통 동선 | 네 가지 첫 화면 진입을 유지하고 보호자 연령 설정을 연결한다. 각 과목은 즉시 학습을 시작한다. 과일 가게와 향후 빵집은 혼합 주문을 시작해 진열대로 이어진다. 주문 ID·가게·연령·보기·정답·결과를 읽는 공통 구조로 0.5 여섯 장면을 옮긴다. 빵집 대표 주문도 같은 구조로 메뉴에서 연다. 저장 버전과 0.5 변환을 함께 작성한다. | 새 설치에서 네 연령·두 가게 선택이 보이고 대표 주문이 실제로 열린다. 기존 여섯 활동, 소리 기본값, 두 입력 방식이 보존된다. 0.5에서 완료한 장과 음소거가 업데이트 뒤 복구된다. |
| **2 · 예정** 전체 교재와 편성 | 두 가게 80개 주문, 과목별 세 번째 변형, 공통 쓰기 경로와 연령별 서랍을 완성한다. 0.6의 한 획 경로들을 한글 자모·한 글자·영문 대문자·숫자·선 놀이로 확장한다. 검수된 문항을 메뉴와 편성기에 연결한다. | 40조합마다 서로 다른 기본 주문 2개가 열린다. 과목 모드와 연필 서랍은 세 장이 서로 구분된다. 후보가 충분할 때 최근 주문과 첫 과목 반복을 피한다. 양 가게 모두 직접·도움·건너뛰기·이어하기가 된다. |
| **3 · 예정** 그림·음성·보호자 기능 통합 | 빵집 배경, 진열대와 결과 소품, 모모 동작, 모드 아이콘을 완성한다. 한국어·영어 대사와 효과음을 연결하고 텍스트·그림 도움을 맞춘다. 보호자가 난이도·소리와 최근 활동을 확인하고 바꿀 수 있게 한다. | 주문에서 언급한 물건·개수·글자·음성과 손으로 만든 결과가 일치한다. 모든 화면을 소리 켜짐으로 처음부터 플레이하고 옵션을 중간에 바꿔도 진행된다. 보호자 이력에서 직접 수행과 도움 수행을 구분한다. |
| **4 · 예정** 실기기 검수와 인도 | 자동 회귀, 문항 전수 검토, 대상 기기 플레이, 수정 후 재시험, 배포용 빌드 및 안내를 한 묶음으로 진행한다. 실기기 관찰은 기기가 확보되는 시점부터 앞 단계와 병행할 수 있다. | 아래 인수 기준을 충족하고 커밋·설치본·서명 정보·확인 기기·남은 제한을 인수인계에 기록한다. |

### 첫 개발 묶음의 구현 메모

- **진입·설정**은 `godot/project.godot`의 `round.tscn`에서 시작한다. 첫 연령 선택 뒤에는 네 놀이 선택 화면으로 이동한다. 각 버튼에서 해당 놀이를 이어간다. 부모가 연령을 바꾸어도 진행 중인 판의 나이와 보기는 그 판을 끝낼 때까지 유지하고 새 판부터 선택한 연령을 쓴다.
- **주문 정의**에는 안정적인 ID, 가게·나이·과목, 학습 목표, 조작 종류, 문항/변형 ID, 보기와 정답, 발화 ID, 그림 도움과 완료 소품을 둔다. 숫자·개수·영어 단복수는 같은 주문 정의에서 읽는다. 글자에는 언어와 순서 있는 획 경로를 연결한다. 캐릭터와 가게를 매 문항 새로 제작할 필요 없이 데이터로 바꿀 수 있게 한다.
- **이어하기**에는 저장 형식 버전, 판의 가게·연령·모드, 이미 정한 문항 ID와 보기 순서, 다음 위치, 제시·완료·도움 이력을 둔다. 주문 완료와 다음 위치를 한 번에 저장한다. 쓰기 도중 종료하면 같은 주문에서 다시 시작한다. 시범을 직접 정답으로 집계하지 않는다.
- **0.5 변환**은 `preferences.cfg`의 소리, `fruit_round.cfg`의 덱·순서·결과를 읽는다. 예전 키 `word/count/english/observe/pattern/trace`는 각각 `F4-K1/F4-M1/F4-E1/F4-O1/F4-P1/F4-M2`에 대응한다. 미완료 덱은 기존 연령과 남은 순서를 보존한다. 빈 저장, 도중 종료, 완료 직후, 손상된 저장을 각각 확인하고 읽을 수 있는 설정은 보존한다.
- **확인 방법**은 새 설치 한 판, 저장 후 앱 종료 → 재실행, 기존 0.5 데이터로 이어하기, 쉬기 중 가게 복귀, 마지막 장 두 번 누르기다. 결과는 브랜치 소스·테스트와 함께 [인수인계](HANDOFF.md)에 남긴다.

0.5는 arm64 디버그 설치본이고 앱 ID는 `org.kkoma.prototype.applemarket`이다. 정식 서명과 기존 디버그 서명이 다르면 Android가 같은 앱 위에 설치하는 업데이트를 거부한다. 배포 경로 결정 시 기존 이용자용 설치·기록 이전 방법과 새 설치를 각각 시험한다. 비밀 키는 저장소 밖에서 관리한다. 배포 채널, 최종 서명 주체, 최종 목소리, 실제 태블릿 모델은 아직 결정·확인이 남아 있다. 현재 단계의 개발은 기록된 기준으로 진행할 수 있다.

## 다른 채팅에서 이어갈 때

README에서 바로 [인수인계](HANDOFF.md)를 연다. 이 문서는 전체 일정과 완료 조건, [제품 기획](PRODUCT_PLAN.md)은 교육·미술 방향, [출시 명세](RELEASE_SPEC.md)는 화면·편성 규칙, [주문 원고](ORDER_CATALOG.md)는 문항별 내용을 관리한다. 구현을 끝낸 작업 단위마다 인수인계 첫 부분에 **검증한 코드 커밋, 실행 가능한 범위, 검증 방법과 결과, 남은 일, 다음 작업**을 갱신한다. 새 채팅에서는 원격 브랜치 최신 상태와 마지막 검증 기록을 대조한 뒤 장부의 다음 묶음을 이어 간다.
