# 음성 제작·검수 준비

## 성우 연기 음원 방향 (2026-10-16)

스토리 음성의 목표는 캐릭터별 감정 연기가 있는 사전 제작 음원이다. 현재 실제 녹음은 **0개**이며 기기 TTS는 임시 대안이다. 사용자는 캐릭터별 AI 연기 음성을 선택했다. [AI 시연 4개 제작 계획과 실행 조건](AI_AUDITIONS.md), `ai_audition_plan.json`을 확인한다. 기본 계획 생성은 API 호출/비용 없이 실행된다. [연기·캐스팅 제작 지침](STORY_DIRECTION.md)을 기준으로 한다. 고정 대본 671개 중 스토리 문맥에 사용되는 **352개 take**의 인물·감정·호흡·파일 ID·시연 후보는 `story_studio.json`에 있다. 시연 후보는 대본 ID이며 들을 수 있는 새 음원을 제작했다는 뜻이 아니다.

```powershell
dart run tool/export_story_studio.dart
# 녹음 전부 존재 + PCM 경고 없음을 요구하는 제작 검사. 청취 승인을 대신하지 않음.
dart run tool/export_story_studio.dart --require-recordings
```

스토리 자동 읽기·다시 듣기·글자 소리 버튼은 정확한 녹음 ID와 원문/언어가 일치할 때만 해당 take를 재생한다. 같은 대사라도 다른 캐릭터·장면의 파일로 대체하지 않는다. 기존 학습 모드의 일반 텍스트/언어 검색은 유지한다. 인덱스에 기록된 화자가 바뀌면 자동 재등록을 막고 재제작·검수를 요구한다. `voice_scripts.json/CSV`에도 인물·감정·연기·호흡 지침을 추가했다. 파일의 peak/RMS·무음·클리핑 검사는 객관적 경고이며 RMS를 LUFS로 표현하거나 성우 연기/발음 검수 완료로 간주하지 않는다.

`voice_scripts.json`은 원본 대본 데이터이고 `voice_scripts.csv`는 사람이 검토할 목록이다. 앱의 학습/스토리 데이터에서 생성한다. CSV는 UTF-8 BOM, 쉼표·따옴표·줄바꿈을 인용한다. 텍스트를 수작업으로 고친 뒤 재생성하면 덮어쓰므로, 문구 수정은 원본 콘텐츠에서 하고 검수 결과는 별도 파일에 남긴다.

```powershell
dart run tool/export_voice_scripts.dart
dart run tool/prepare_recordings.dart
dart run tool/prepare_recordings.dart --check
dart run tool/audit_content.dart
# 녹음이 모두 준비되어야 성공시키는 별도 제작 검사
dart run tool/export_voice_scripts.dart --require-recordings
```

현재 **671개 대본(한국어 564 / 영어 107)**이며 실제 녹음 파일은 **0개**다. 기존 609개에 12화 장면 놀이의 초대/발견 완료/복원 시 읽기 60개를 추가했다. 새 대본은 `scene-play` 범주이며 자동 읽기·다시 듣기·저장 후 발견 반응에 쓰인다. 대본 추가를 음원 제작 완료로 보고하지 않는다. 앞선 388→609개 재산정은 필기 글자 이름·만 2세 대사·성공/선택 결과·1~5개 세기 추가에 따른 것이다. 동적 힌트/오류/도움/완료 안내, 분류 놀이의 합성 피드백은 고정 목록 밖에서 TTS로 남긴다. 6·11화 그림 속 배치의 조작 안내 2개를 추가했고, 해당 화자/대사·개수 질문도 갱신했다. 이 2개는 `world-mission` 범주다. 671개는 실행 중 모든 발화의 총수가 아니다.

목록 필드:

| 필드 | 용도 |
|---|---|
| id / file | 고유 ID와 제안 저장 위치 `assets/audio/<id>.wav` |
| language | 실제 요청 언어 `ko-KR` 또는 `en-US` |
| category / contexts | 학습·필기·퀴즈·대사·선택·세기와 사용 장면/경로 |
| text | 읽을 원문. 스토리 줄바꿈은 문장 사이 쉼으로 처리 |
| review | 이름/소리 구분, 개수 읽기, 특정 단어의 검수 주의점 |
| file_status | missing / invalid / format-valid-unreviewed |
| listening_review | 모든 항목 pending. 사람이 듣고 검수한 것으로 자동 변경하지 않음 |

제작 순서는 1화와 만 2세 짧은 안내 → 글자 이름과 대표 단어 샘플 → 나머지 장면/퀴즈를 권장한다. 따뜻하고 차분한 말투, 문장 사이 쉼, 놀라게 하는 큰 음량/빠른 말/과도한 효과를 피한다. 영어 알파벳 이름과 대표 단어를 분리해 검수하고, Apple 단어 전체를 첫소리 클립으로 표기하지 않는다. X/Fox의 x는 끝에 있으므로 첫소리 예시로 설명하지 않는다. 숫자 기호와 `개`의 수량 표현은 서로 다른 읽기를 확인한다. 한글 자음 이름·모음 소리·음절/낱말도 구분한다.

파일 검사는 RIFF/WAVE 구조·길이·청크·PCM16 mono·16~48kHz·byte rate·0초/60초 초과를 검사한다. 파일 형식 통과는 실제 발음, 정답 유출, 소리 크기, 무음·클리핑, 어린이 적합성 검수를 대신하지 않는다. 이 도구는 녹음·외부 전송·유료 서비스 호출을 수행하지 않는다.

**녹음 우선 재생과 오프라인 TTS 대체가 연결되어 있다.** 현재 실제 음성 WAV는 0개여서 모든 음성은 TTS로 읽는다. 파일을 제작하고 사람이 검수한 뒤 `assets/audio/<id>.wav`에 넣고 `prepare_recordings.dart`를 실행한다. 도구는 존재하는 형식 유효 파일만 `assets/audio/recordings.json`에 원문·언어·바이트 길이와 함께 등록한다. 앱은 요청 텍스트와 언어가 모두 일치할 때만 녹음을 사용한다. 스토리의 지정 take는 다른 ID와 공유하지 않는다. 지정 ID가 없는 일반 학습 요청만 같은 텍스트/언어의 첫 번째 등록 파일을 공유할 수 있다. 파일 형식 검사는 발음·내용 청취 검수가 아니다.

기존 등록 파일의 원문이나 언어가 바뀌면 자동으로 새 대본을 붙이지 않고 빌드를 중단한다. 재녹음·검수 후 해당 인덱스 항목을 의도적으로 갱신하고 다시 생성한다. 알 수 없는 ID의 WAV·잘못된 WAV·깨진 기존 인덱스도 제작 오류로 처리한다. `tool/android.ps1 build ...`는 빌드 전에 이 검사를 실행한다. Flutter를 직접 실행/빌드할 때는 위 생성·검사를 먼저 수행해야 한다.

Android는 로컬 번들 WAV를 MediaPlayer로 끝까지 재생한 뒤 완료를 돌려준다. 누락·디코딩 실패·시간 초과에는 재생기를 정지한 뒤 남은 반복만 TTS로 읽는다. 화면 이탈·새 요청·백그라운드·오디오 포커스 상실로 취소되면 자동 대체 재생하지 않는다. 음성 음량·반복은 보호자 설정을 따르고 효과음과 독립적이다. 배경음악은 미제작이며 효과음 3개와 구분한다. 실제 Android 청취·기기 언어팩·설치/업데이트·성능 검증은 사용자의 지시대로 최종 단계에 수행한다.
