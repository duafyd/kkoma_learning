# 꼬마 탐험 공부방 뼈대 (v1.1)

> 이 문서를 ChatGPT, Claude, Cursor 등 코딩 에이전트에게 통째로 제공하고 아래처럼 요청한다.
>
> **“이 명세를 기준으로 Flutter와 Dart를 사용해 Galaxy Tab용 어린이 교육 앱 전체를 개발해라. MVVM + Riverpod + Repository 및 Feature-first 구조를 따르고, 내부적으로 단계별 구현·검증을 반복해라. 매 단계마다 사용자 승인을 기다리지 말고 진행 상태를 docs/PROGRESS.md에 기록해라.”**
>
> 이 프로젝트는 만 2~5세 어린이가 보호자와 함께 또는 보호자가 설정한 환경에서 사용하는 태블릿 교육 앱이다. 한글·영어·수학 학습, 글자 따라 쓰기, 자유 그림 그리기, 선택형 스토리텔링을 제공한다.
>
> **기술 기준:** Flutter + Dart, 우선 대상은 Samsung Galaxy Tab Android 태블릿, 우선 결과물은 설치 가능한 APK다. OpenAI Realtime API와 실시간 음성 AI는 사용하지 않는다.

## 0. 프로젝트 목표와 개발 원칙

### 0-1. 제품 목표

아이에게 문제를 많이 풀게 하는 앱이 아니라, **듣고 → 보고 → 손가락으로 해 보고 → 선택하고 → 이야기 속에서 써 보는** 놀이형 학습 앱을 만든다.

- 대상 연령: 만 2~5세
- 주요 과목: 한글, 영어, 수학·기초 산수
- 주요 활동: 글자·숫자 읽어 주기, 획을 따라 그리기, 자유 그림, 그림책형 스토리텔링, 중간 퀴즈
- 이야기의 진행: 에피소드마다 완결감이 있으면서도 하나의 큰 이야기와 세계관이 이어진다.
- 실행 환경: Android 태블릿, 우선 Galaxy Tab
- 기본 사용 방식: 오프라인에서도 핵심 학습 콘텐츠와 저장된 진도를 이용할 수 있다.
- 첫 버전은 한 기기에서 동작하는 로컬 앱으로 만든다. 계정·서버·광고·결제는 초기 범위에서 제외한다.

### 0-2. 핵심 원칙

1. **연령보다 실제 수행 수준을 우선한다.** 나이는 기본 학습 경로를 정하는 기준일 뿐, 아이를 평가하거나 낙인찍는 용도로 쓰지 않는다.
2. **짧고 성공적인 활동을 우선한다.** 한 활동은 대체로 2~5분 이내로 구성하고, 어린 연령은 더 짧게 한다.
3. **실패해도 이야기 진행을 막아 좌절시키지 않는다.** 스토리 모드에서 필수 미션은 재시도·힌트·쉬운 경로를 제공한다. 반복 실패 시 보호자가 설정한 횟수 후에는 도움 모드로 통과할 수 있다.
4. **정답만 칭찬하지 않는다.** 시도, 집중, 획의 방향, 다시 해 본 행동을 구체적으로 칭찬한다.
5. **광고·외부 링크·불필요한 개인정보 입력은 금지한다.**
6. **아이 혼자 설정을 바꾸거나 앱을 종료하기 어렵게 하되, 보호자에게는 명확한 보호자 영역을 제공한다.**
7. **모든 소리·애니메이션은 끌 수 있어야 한다.** 효과음과 음성은 반복 재생을 과도하게 하지 않는다.
8. **학습 콘텐츠와 화면 코드를 분리한다.** 글자, 획 데이터, 문제, 스토리 장면은 JSON 또는 Dart 데이터 모델로 관리한다.
9. **핵심 기능부터 완성한다.** 초기부터 거대한 게임 엔진·서버·생성형 AI를 도입하지 않는다.

### 0-3. 초기 범위와 제외 범위

**첫 버전에 포함**
- 연령 선택과 보호자 설정
- 한글·영어·수학 학습 홈
- 한글/알파벳/숫자 따라 그리기
- 자유 그림 그리기
- 그림책형 스토리 모드와 장면 내 퀴즈
- 오디오 읽어 주기, 효과음, 간단한 캐릭터 애니메이션
- 학습 진도와 그림 저장
- 보호자 영역, 사용 시간 설정, 소리 설정
- Galaxy Tab 가로 화면 최적화와 APK 빌드

**첫 버전에서 제외**
- OpenAI Realtime API, 실시간 음성 대화, 음성 녹음
- 회원 가입·클라우드 동기화·다중 기기 동기화
- 광고, 인앱 결제, 공개 커뮤니티
- AI가 즉석에서 만드는 이야기나 이미지를 그대로 아이에게 노출하는 기능
- 복잡한 3D 그래픽과 온라인 멀티플레이

## 1. 연령별 교육 설계

연령은 만 나이를 기준으로 하며, 보호자가 언제든 학습 단계를 바꿀 수 있다. 각 연령의 활동 시간은 권장 범위이지 강제 제한이 아니다.

### 1-1. 만 2세: 소리·그림·터치 탐색

목표는 정답 맞히기보다 소리와 그림을 연결하고 화면을 터치해 원인과 결과를 경험하는 것이다.

- **한글:** 친숙한 사물 그림과 소리 듣기, 자기 이름에 포함된 글자에 노출되기, 같은 그림 찾기. 자음·모음을 외우게 하기보다 소리와 그림을 자연스럽게 연결한다.
- **영어:** 동물·색·장난감 등 친숙한 단어를 듣고 그림을 누르기. 알파벳은 노출과 친숙함 중심.
- **수학:** 하나/많다, 크다/작다, 같은 것 찾기, 1~3개 사물 세어 보기.
- **그리기:** 큰 점·선·원 따라 움직이기, 손가락으로 자유롭게 색칠하기. 정확도 점수는 매기지 않는다.
- **스토리:** 3~5장면의 짧은 그림책. 장면마다 탭 한 번 또는 두 가지 그림 중 선택하기. 정답이 없는 선택도 포함한다.
- **UI:** 큰 버튼, 한 화면 한 가지 행동, 짧은 문장, 음성 안내, 자동 읽기 선택 옵션.

### 1-2. 만 3세: 기초 글자와 수량 연결

- **한글:** 모양이 다른 자음·모음 알아보기, 기본 모음과 친숙한 자음 소리 듣기, 글자와 그림 연결, 점선·큰 획 따라 그리기.
- **영어:** 대문자 중심으로 알파벳 모양과 대표 단어 연결, 첫소리 듣기, 점선 따라 그리기.
- **수학:** 1~5 세기, 숫자와 수량 매칭, 같은 수끼리 모으기, 도형·색·크기 분류, 간단한 패턴.
- **그리기:** 직선·곡선·원 따라 그리기, 자유 그림 도구 사용.
- **스토리:** 5~7장면. 중간에 그림 선택, 수량 세기, 글자·알파벳 한 번 따라 그리기 중 하나를 넣는다.

### 1-3. 만 4세: 조합·비교·간단한 문제 해결

- **한글:** 자음과 모음의 모양을 구분하고 쉬운 음절을 관찰·조합하기(예: 가, 나, 모). 획 순서와 방향을 익히고 글자 따라 그리기.
- **영어:** 대문자와 소문자 짝짓기, 알파벳과 대표 단어·첫소리 연결, 글자 따라 그리기.
- **수학:** 1~10 세기, 숫자-수량 연결, 하나 더/하나 덜, 많다/적다, 간단한 분류와 순서 패턴.
- **그리기:** 획 방향과 시작점 안내, 여러 글자·숫자 연속 따라 쓰기, 자유 그림 저장.
- **스토리:** 7~9장면. 이야기 진행에 한글·영어·수학 퀴즈를 번갈아 넣되 한 장면에 과제를 과하게 넣지 않는다.

### 1-4. 만 5세: 읽기 준비·기초 연산·응용

- **한글:** 쉬운 음절과 짧은 낱말을 소리와 연결하기, 자음·모음 조합, 글자 따라 쓰기, 익숙한 낱말 찾아보기.
- **영어:** 대문자·소문자 인식, 알파벳 순서, 대표 단어와 첫소리 연결, 짧고 쉬운 단어를 그림과 연결하기.
- **수학:** 1~20 범위의 수 세기, 수량 비교, 10 이하의 구체물 더하기·빼기, 간단한 규칙 찾기와 도형 분류.
- **그리기:** 글자·숫자 획 순서와 완성도 피드백, 짧은 낱말이나 숫자 묶음 연습.
- **스토리:** 8~12장면. 선택의 결과가 다음 장면에 영향을 주고, 이전 에피소드에서 배운 내용이 자연스럽게 다시 등장한다.

### 1-5. 연령별 난이도 조정 규칙

- 정답/성공이 이어지면 다음 활동에서 한 단계만 어려워진다.
- 같은 유형을 연속으로 틀리면 문제를 반복해서 압박하지 말고, 음성 힌트·시각 힌트·더 쉬운 문제 중 하나를 제공한다.
- 글자 따라 그리기 평가는 획의 시작점, 방향, 경로와의 거리, 완료 여부를 종합한다. 한 번의 손 떨림이나 태블릿 가장자리 터치로 실패 처리하지 않는다.
- 만 2~3세는 획의 정확도를 엄격히 평가하지 않는다. 화면에 대략적인 경로를 그려도 완료로 인정할 수 있다.
- 연령별 콘텐츠는 보호자가 직접 조정할 수 있고, 아이에게 “못한다”, “낮은 단계” 같은 표현을 노출하지 않는다.

## 2. 앱 정보 구조

### 2-1. 메인 메뉴

1. **오늘의 모험** — 이어지는 스토리의 다음 장면
2. **한글 놀이터** — 글자 듣기, 자음·모음 탐색, 따라 쓰기
3. **English Garden** — 알파벳 듣기, 대문자·소문자, 따라 쓰기
4. **숫자 탐험대** — 수 세기, 숫자 그리기, 기초 산수
5. **자유 그림방** — 빈 캔버스, 색칠, 스티커, 저장
6. **내 작품·모험 지도** — 저장한 그림, 완료한 이야기, 획득한 꾸미기 보상
7. **보호자 영역** — 연령·난이도·음량·사용 시간·진도 설정

### 2-2. 태블릿 UI 기준

- 우선 Galaxy Tab의 가로 방향을 기준으로 설계하되, 기기 설정에 따라 세로 방향에서도 레이아웃이 깨지지 않도록 한다.
- 기준 레이아웃은 16:10 태블릿 비율을 우선 고려하되 특정 해상도에 고정하지 않는다.
- 화면 터치 대상은 충분히 크게, 주요 버튼은 가장자리와 너무 가까이 두지 않는다.
- 글자·숫자·퀴즈 그림은 멀리서도 알아보기 쉬운 크기와 높은 대비를 사용한다.
- 텍스트만으로 지시하지 말고 그림·음성·애니메이션을 함께 쓴다.
- 화면 전환은 짧고 예측 가능하게 한다. 깜빡임, 과도한 흔들림, 빠른 섬광은 사용하지 않는다.
- 시스템 뒤로 가기·앱 종료는 실수로 눌러도 진행 중인 활동이 사라지지 않게 처리한다.
- 부모 설정 진입은 아이 화면의 단순한 터치만으로 열리지 않게 하고, 간단한 보호자 확인 절차를 둔다.

## 3. 학습 모드 상세

### 3-1. 글자·숫자 듣기 모드

각 글자나 숫자를 화면에 크게 보여 주고, 눌렀을 때 이름 또는 소리를 재생한다.

- 한글은 자음 이름과 대표 소리를 구분해서 가르친다. 예를 들어 글자 이름을 읽어 준 뒤 대표 단어를 들려준다.
- 모음은 글자 이름과 실제 발음 예시를 함께 제공한다.
- 영어는 알파벳 이름과 대표 단어를 구분한다. 알파벳 이름과 단어 첫소리가 항상 같다고 오해하지 않도록 예시를 고른다.
- 숫자는 숫자 이름, 수량 그림, 간단한 세기 활동을 연결한다.
- 음성은 기본적으로 사전에 준비한 녹음 파일을 사용한다. Android TTS를 대안으로 쓸 수 있으나 기기·엔진별 발음 차이를 테스트한다.
- 부모 설정에서 자동 읽기, 반복 횟수, 음성·효과음 음량을 바꿀 수 있다.
- 음성 파일이 없거나 재생 실패가 나도 화면과 활동은 계속 이용할 수 있어야 한다.

### 3-2. 한글·알파벳·숫자 따라 그리기 모드

**기본 흐름**
1. 큰 글자와 시작점을 보여 준다.
2. 음성으로 글자 이름이나 소리를 알려 준다.
3. 애니메이션으로 획을 천천히 시범 보인다.
4. 점선 또는 넓은 경로를 따라 손가락으로 그린다.
5. 완료하면 부드러운 애니메이션과 짧은 칭찬을 보여 준다.
6. 다음 글자, 다시 해 보기, 그만하기 중 하나를 선택한다.

**그리기 요구사항**
- `CustomPainter`와 포인터/터치 이벤트를 기본으로 검토한다.
- 획 데이터는 시작점, 진행 경로, 순서, 방향, 허용 오차를 갖는 데이터 모델로 저장한다.
- 단순히 글자 외곽선 안에 그렸는지만 보지 말고, 획의 순서와 방향을 고려한다.
- 획이 여러 개인 글자는 한 번에 전부 그리게 하지 않고 현재 획을 강조한다.
- 손가락을 떼거나 화면 밖으로 나가도 앱이 멈추지 않고 자연스럽게 이어지거나 재시도할 수 있게 한다.
- 지우기, 다시 하기, 시범 보기 버튼을 제공한다.
- 오답음·빨간 X·감점은 사용하지 않는다. 경로에서 벗어나면 부드러운 시각 힌트를 보여 준다.
- 만 2~3세에는 넓은 경로와 느슨한 판정, 만 4~5세에는 점진적으로 좁은 경로와 획 순서를 적용한다.
- 한글 글꼴을 획 데이터로 자동 변환하는 것만으로 정확한 필순을 보장할 수 없으므로, 콘텐츠별 획 경로를 검수한다.
- 글자별 획 데이터가 아직 준비되지 않았다면 지원하지 않는 글자를 활성화하지 말고, 준비된 글자만 제공한다.

### 3-3. 자유 그림 그리기 모드

- 빈 캔버스, 여러 색상, 브러시 굵기, 지우개, 전체 지우기, 실행 취소·다시 실행을 제공한다.
- 만 2~3세는 색상 버튼과 브러시를 크게 만들고 도구 수를 제한한다.
- 만 4~5세는 스티커, 도형 도장, 배경 선택을 추가할 수 있다.
- 저장한 그림은 기기 내부에 PNG 등 이미지 형식으로 저장하고 작품 목록에서 다시 볼 수 있다.
- 그림 저장 시 파일명은 자동 생성한다. 아이의 실명 등 개인정보를 기본 파일명에 넣지 않는다.
- 작품을 삭제하기 전에 확인을 받고, 저장 공간이 부족할 때는 보호자에게 알린다.
- 그림은 기본적으로 기기 밖으로 전송하지 않는다.
- 캔버스는 화면 회전이나 앱 일시 중지 후에도 가능한 한 복구한다.

### 3-4. 수학·산수 모드

- 사물 세기, 숫자 고르기, 숫자 따라 그리기, 같은 수량끼리 연결하기, 크기·모양·색 분류, 패턴 완성, 구체물을 이용한 더하기·빼기 순으로 확장한다.
- 만 2~3세는 수식보다 실제 그림의 수량을 다룬다.
- 만 4~5세는 사물을 화면에서 옮겨 모으거나 하나씩 추가·제거해 연산을 보여 준다.
- 답을 선택하면 사물이 실제로 추가되거나 없어지는 시각적 피드백을 제공한다.
- 숫자만 읽고 맞히는 퀴즈를 연속으로 배치하지 않는다. 세기·비교·분류·패턴을 섞는다.
- 각 문항은 하나의 명확한 정답을 가져야 하며, 그림이나 배치 때문에 답이 모호해지지 않게 테스트한다.

## 4. 스토리텔링 모드: 이어지는 메인 스토리

### 4-1. 핵심 콘셉트 — 《별빛 도서관과 사라진 이야기》

**장르:** 따뜻한 판타지 모험, 그림책과 가벼운 인터랙티브 게임의 결합

**세계관:** 구름 위 작은 마을에는 세상의 모든 이야기가 모이는 ‘별빛 도서관’이 있다. 도서관의 책들은 한글 글자, 영어 알파벳, 숫자와 모양의 별빛으로 살아난다. 어느 날 바람 장난꾸러기 ‘휙휙’이 도서관의 별빛 책장을 흔들어 이야기의 길을 여러 곳으로 흩어 놓는다. 글자 요정 ‘모아’, 꼬마 여우 ‘루루’, 숫자 거북 ‘토토’와 아이는 흩어진 이야기 조각을 찾아 도서관을 복원한다.

**중요한 방향:** 휙휙은 악당이 아니라 실수하고 장난을 치지만 친구들과 함께 바로잡는 캐릭터다. 무서운 장면, 위험한 상황의 사실적인 묘사, 벌을 주는 전개는 피한다. 각 에피소드가 끝날 때 작은 성취가 있고, 마지막에는 앞서 모은 조각들이 하나의 큰 결말로 이어진다.

### 4-2. 주요 캐릭터

- **모아(글자 요정):** 한글과 영어 글자를 발견하면 빛으로 보여 준다. 설명은 짧고 차분하다.
- **루루(꼬마 여우):** 호기심이 많고 아이와 함께 실수한다. 질문을 던지고 선택을 기다린다.
- **토토(숫자 거북):** 천천히 세고 비교한다. 수학 문제를 그림 속 사물로 바꿔 보여 준다.
- **휙휙(바람 친구):** 물건을 흩뜨리는 장난을 치지만 고의로 괴롭히지 않는다. 아이가 도와주면 잘못을 인정하고 함께 해결한다.
- **아이(플레이어):** ‘이야기 탐험가’. 이름 입력 없이도 진행할 수 있고, 캐릭터 이름이나 외모를 개인화하는 기능은 나중에 선택적으로 추가한다.

### 4-3. 이어지는 시즌 1 — 12개 에피소드

각 에피소드는 약 5~10분을 목표로 하되, 만 2~3세용은 장면 수와 퀴즈 수를 줄인다. 언제든 중간 저장·중단·이어하기가 가능해야 한다. 아래 스토리는 세계관과 사건이 순서대로 이어지며, 각 장에서 배운 요소가 뒤 에피소드에 다시 등장한다.

1. **빛을 잃은 도서관**  
   아이는 모아·루루·토토를 만나고 도서관의 별빛이 사라진 이유를 알게 된다. 흩어진 별 조각 1~3개를 찾고, 그림에서 같은 모양을 고른다. 마지막에 작은 별빛 하나가 켜져 탐험 지도가 나타난다.

2. **모음 꽃밭의 길**  
   별빛 지도는 모음 꽃밭을 가리킨다. 꽃들은 ‘ㅏ, ㅓ, ㅗ, ㅜ’ 모양의 문을 가지고 있지만 길이 섞여 있다. 아이는 글자를 듣고 같은 모양을 찾고, 준비된 단계에서는 모음의 획을 따라 그려 문을 연다. 열린 문 뒤에서 다음 별 조각을 발견한다.

3. **자음 나무의 열매**  
   루루가 열매를 담을 바구니를 찾는다. 나무에는 자음 모양 열매가 열려 있다. 아이는 친숙한 그림과 글자를 연결하고, 준비된 단계에서는 자음 하나를 따라 그린다. 열매가 모여 ‘글자 씨앗’이 된다.

4. **뒤죽박죽 소리 기차**  
   도서관으로 돌아가는 기차의 표지와 소리가 뒤섞였다. 아이는 그림을 보고 알맞은 표지를 고르거나, 들려주는 한글 소리와 글자를 연결한다. 만 4~5세는 쉬운 음절을 관찰하고 조합한다. 기차가 도서관의 오래된 역으로 향한다.

5. **알파벳 등대**  
   오래된 역의 등대가 꺼져 있다. 등대에는 영어 알파벳 빛이 필요하다. 아이는 대문자와 대표 단어 그림을 연결하고 알파벳을 따라 그린다. 이후 에피소드에서도 이 알파벳이 영어 표지판과 사물 이름으로 다시 등장한다.

6. **숫자 다리와 세 개의 돌**  
   다리를 건너려면 돌을 순서대로 놓아야 한다. 아이는 사물 수를 세고 숫자와 수량을 연결한다. 연령이 높은 경우 하나 더·하나 덜 문제를 푼다. 다리가 완성되며 도서관 지하 정원으로 이어진다.

7. **색깔을 잃은 정원**  
   정원의 색깔과 모양이 뒤섞였다. 아이는 색·모양·크기를 분류하고 패턴을 완성한다. 자유 그림 모드와 연계해 아이가 정원에 꽃이나 나비를 그려 넣을 수 있다. 정원의 그림이 다음 장의 지도를 만든다.

8. **바람 친구 휙휙의 실수**  
   휙휙이 장난을 치다가 이야기 조각을 너무 멀리 날려 보냈다는 사실이 드러난다. 아이는 흩어진 글자·알파벳·숫자를 찾아 분류한다. 휙휙은 사과하고 함께 조각을 찾기로 한다. 비난이나 벌 대신 협력으로 문제를 해결한다.

9. **세 갈래 이야기 길**  
   지도에는 한글 길, 영어 길, 숫자 길이 나타난다. 아이는 원하는 길을 선택하지만 세 길 모두 같은 이야기의 서로 다른 부분을 보여 준다. 길마다 연령과 학습 이력에 맞춘 짧은 복습 미션이 있다. 어느 길을 먼저 선택해도 이후 스토리의 핵심 사건은 이해할 수 있다.

10. **비 오는 종이숲**  
    비에 젖은 책 페이지가 붙어 있다. 아이는 장면 순서를 맞추고, 빠진 그림을 고르며, 글자나 알파벳 하나를 따라 그려 페이지를 복원한다. 페이지가 이어지면서 휙휙이 왜 이야기를 흩뜨렸는지에 대한 단서가 나온다.

11. **마지막 별자리 퍼즐**  
    지금까지 모은 별 조각을 하늘에 배치해야 한다. 아이는 수량을 세고, 모양과 패턴을 맞추고, 준비된 글자·알파벳을 다시 그린다. 앞에서 배운 내용을 무작위 시험처럼 내지 않고 이야기의 문제를 해결하는 데 사용한다.

12. **다시 열린 별빛 도서관**  
    별 조각들이 모여 도서관의 이야기를 복원한다. 휙휙도 자신이 좋아하는 이야기를 함께 만들고 싶어서 장난을 쳤다는 마음을 말한다. 친구들은 그 마음을 이해하되, 다른 사람의 것을 흩뜨리면 함께 정리해야 한다는 점을 배운다. 아이가 모은 별빛으로 도서관의 방을 꾸미고, 시즌 2로 이어질 새 책 한 권이 나타난다.

### 4-4. 스토리 장면 구성 규칙

각 에피소드는 아래 데이터 구조로 작성한다.

- 에피소드 ID, 제목, 권장 연령, 핵심 학습 목표
- 장면 순서, 배경 이미지, 캐릭터 위치·표정, 대사 텍스트
- 대사 오디오 파일과 효과음 ID
- 사용자 입력 유형: 탭, 두 그림 중 선택, 드래그, 글자 따라 그리기, 숫자 문제
- 정답 조건, 힌트 단계, 실패 시 대응, 통과 조건
- 성공 시 애니메이션, 획득 보상, 다음 장면 ID
- 이전 선택이 영향을 주는 변수(초기 버전은 단순한 플래그만 사용)

대사는 어린이가 이해할 짧은 문장으로 쓴다. 한 장면에서 긴 설명을 읽게 하지 말고, 말풍선·음성·행동을 조합한다. 모든 대사는 텍스트로도 제공하고 음성은 선택적으로 끌 수 있게 한다.

### 4-5. 스토리 퀴즈와 통과 규칙

- 퀴즈는 이야기 안에서 자연스럽게 나온다. “시험이야”라고 말하기보다 친구를 돕거나 길을 찾는 상황으로 제시한다.
- 문제 유형은 그림 고르기, 사물 세기, 분류하기, 간단한 패턴, 글자·알파벳 따라 그리기다.
- 만 2세는 정답이 없는 상호작용과 한 번의 탭 중심으로 진행한다. 정답 필수 관문은 두지 않는다.
- 만 3~5세는 핵심 장면에서 학습 활동을 완료하면 다음 장면으로 이동한다. 단, 반복 실패 시 시범 보기 → 함께 하기 → 쉬운 문제로 바꾸기 → 보호자 설정에 따른 도움 통과 순으로 지원한다.
- 따라 그리기 관문은 글자 획 전체를 엄격하게 평가하기보다, 해당 연령의 허용 오차와 시도 횟수를 고려한다.
- 틀렸을 때 “틀렸어” 대신 “이쪽 길도 살펴볼까?” 같은 문구를 사용한다.
- 답을 맞히면 별빛, 캐릭터 반응, 효과음 중 일부를 제공한다. 보상은 학습을 계속하게 돕는 정도로 제한하고, 과도한 연속 보상·랜덤 상자·결제 유도는 사용하지 않는다.
- 에피소드의 핵심 스토리는 학습 경로가 달라도 유지한다. 특정 글자를 못 그려서 이야기를 영구적으로 진행할 수 없는 상태가 생기면 안 된다.

## 5. 콘텐츠·오디오·그래픽 제작 기준

### 5-1. 콘텐츠 원칙

- 글자·숫자·단어·문제는 연령과 학습 목표가 명확해야 한다.
- 한국어 글자 이름, 대표 소리, 예시 단어를 혼동하지 않도록 콘텐츠 검수를 한다.
- 영어 알파벳 이름과 단어의 첫소리를 구분한다.
- 수학 문항은 그림만 봐도 조건이 명확하고 정답이 하나인지 검수한다.
- 아이에게 보여 주는 글은 짧고 구체적으로 쓴다.
- 학습 콘텐츠는 코드에 하드코딩하지 말고 JSON 또는 별도 데이터 파일로 관리한다.
- 외부에서 내려받은 콘텐츠를 그대로 신뢰해 실행하지 않는다. 초기 버전의 콘텐츠는 앱과 함께 배포한다.

### 5-2. 오디오

- 기본은 사전 녹음된 음성 파일을 사용한다. 필요하면 Android TTS를 보조 수단으로 사용한다.
- 한글·영어 음성은 언어별로 검수한다.
- 모든 오디오에 고유 ID를 부여하고, 누락 파일 검사 도구를 만든다.
- 효과음은 짧고 부드럽게, 반복 재생을 피한다.
- 음성·효과음·배경음악 볼륨을 별도로 설정할 수 있다.
- 화면 전환이나 앱 일시 중지 시 필요 없는 소리는 멈춘다.
- 음성 파일이 없어도 앱이 크래시하지 않고 자막 또는 기본 동작으로 진행한다.

### 5-3. 그래픽·애니메이션

- 2D 그림책 스타일을 기본으로 한다. 선명하고 따뜻한 색, 단순한 실루엣, 일관된 캐릭터 디자인을 사용한다.
- 배경과 캐릭터를 가능한 한 분리된 에셋으로 준비해 표정·위치를 재사용한다.
- 첫 버전은 Flutter의 기본 애니메이션과 `CustomPainter`를 우선 사용한다.
- 장면 안에서 물리·충돌·여러 스프라이트의 지속적 이동이 많아지는 경우에만 Flame 도입을 검토한다.
- 정적인 그림책 장면마다 게임 엔진을 적용하지 않는다.
- 앱 크기와 메모리를 관리하고, 큰 이미지는 태블릿 해상도에 맞는 크기로 최적화한다.

## 6. 기술 스택과 앱 구조

### 6-1. 기본 기술

- **언어:** Dart
- **UI:** Flutter
- **우선 플랫폼:** Android, Samsung Galaxy Tab
- **배포:** APK 우선
- **그리기:** `CustomPainter`, 포인터/터치 이벤트
- **애니메이션:** Flutter Animation
- **2D 게임 기능:** 복잡한 장면이 필요한 경우 Flame 검토
- **로컬 저장:** 초기에는 `shared_preferences`로 설정값, SQLite 또는 Isar/Hive 등 검토된 로컬 저장소로 진도·작품 메타데이터를 저장한다. 저장소는 프로젝트 초기에 하나를 선택하고 중복 도입하지 않는다.
- **이미지 저장:** 기기 내부 앱 전용 저장 공간
- **오디오:** 검토된 Flutter 오디오 패키지 한 가지를 선택하고, 앱 생명주기·중단·동시 재생을 테스트한다.
- **네트워크:** 핵심 기능에 필수 아님. 첫 버전은 오프라인 동작을 기본으로 한다.

패키지 이름과 API는 개발 시작 시 최신 안정 버전과 Android 지원 범위를 확인한다. 무조건 많은 패키지를 넣지 말고, 유지보수 상태와 라이선스를 검토한 뒤 선택한다.

### 6-4. 상태·아키텍처

- 화면 UI와 학습 진행 로직을 분리한다.
- 처음부터 복잡한 상태관리 프레임워크를 도입하기보다, 프로젝트 초기에 한 가지 방식(예: Riverpod 또는 Flutter 기본 상태 관리)을 선택하고 일관되게 사용한다.
- 비즈니스 로직은 가능한 한 순수 Dart 코드로 작성해 테스트할 수 있게 한다.
- 스토리 진행 상태는 `currentEpisodeId`, `currentSceneId`, `flags`, 완료 상태로 저장한다.
- 앱이 중단되거나 태블릿이 잠겨도 마지막 진행 장면을 복원한다.
- 예외와 누락된 에셋을 처리하고, 개발 모드에서 콘텐츠 오류를 쉽게 찾을 수 있게 로그를 남긴다.
- 아이의 이름, 사진, 음성 등 민감한 데이터를 기본적으로 수집하지 않는다.

### 6-5. 확정 아키텍처 (v1.1 우선 적용)

- **MVVM + Riverpod + Repository**를 기본으로 한다. Riverpod은 디자인 패턴 자체가 아니라 상태 관리·의존성 주입 도구다.
- **Feature-first** 폴더 구조로 각 기능의 `presentation`(pages/widgets/view_models), `domain`(models/rules), `data`(repositories/data_sources)를 필요에 따라 묶는다. 작은 기능은 불필요한 하위 계층을 생략한다.
- 상태 관리에는 `flutter_riverpod`의 `Notifier` / `AsyncNotifier`를 우선 사용하고, 동기 UI 로컬 상태는 필요하면 `StatefulWidget`을 쓴다. 초기에는 `riverpod_generator` 등 코드 생성 의존성을 필수로 두지 않는다.
- 화면 이동은 `go_router`, 외부 저장소 접근은 Repository를 통해서만 수행한다.
- 스토리 흐름은 `StoryPhase`(dialogue, quiz, tracing, success, nextScene 등)와 명시적 전이 규칙을 갖춘 **State Machine**으로 만든다.
- 연령별 난이도, 힌트, 획 허용 오차 및 판정은 **Strategy** 형태의 교체 가능한 순수 Dart 정책으로 분리한다. 패턴을 위해 불필요한 인터페이스를 남발하지 않는다.
- 화면 위젯에 저장소 접근·정답 판정·스토리 분기 로직을 직접 작성하지 않는다. ViewModel은 UI 상태와 사용자 의도를 조율하고, 계산·판정은 테스트 가능한 서비스/정책에 둔다.
- 전역 상태는 최소화하고, 스토리·필기·학습 세션별로 상태의 생명주기를 분리한다. 큰 캔버스의 모든 포인터 이동을 앱 전체 Provider 갱신으로 전파하지 않는다.
- 의존성은 필요한 기능에만 추가한다. 앱은 **Android 전용으로 우선 개발**하며 Windows 데스크톱 빌드는 요구하지 않는다.

권장 구조 예시:

```text

  main.dart
  app/                 # ProviderScope, MaterialApp.router, go_router, theme
  core/                # 공통 오디오, DB, 파일, 그림 엔진, 공용 위젯
  features/
    home/presentation/
    profile/{presentation,domain,data}/
    hangul/{presentation,domain,data}/
    english/{presentation,domain,data}/
    math/{presentation,domain,data}/
    tracing/{presentation,domain}/
    drawing/{presentation,domain,data}/
    story/{presentation,domain,data}/
    progress/{presentation,domain,data}/
    parent/{presentation,domain,data}/
  shared/              # 여러 기능에서 실제 공유되는 모델/정책만
assets/                # story, audio, images, learning content
integration_test/
test/

```

## 9. 개발 로드맵 — 단계별 구현

에이전트에게 **전체 앱 개발을 한 번에 지시한다.** 다만 내부 구현은 아래 순서로 작게 나누고, 매 단계에서 실행 가능한 앱을 유지하며 테스트 후 다음 단계로 **사용자 승인 없이 자동 진행**한다. 작업 제한으로 중단되면 `docs/PROGRESS.md`에 재개 지점을 남긴다.

### 1단계. 요구사항·개발 환경 확정
- Flutter stable, Dart, Android SDK, Gradle/JDK 버전을 확인한다.
- Galaxy Tab 모델과 Android 버전, 화면 비율, 방향을 기록한다.
- 새 Flutter 프로젝트를 만들고 실제 태블릿에 디버그 APK를 설치한다.

**완료 기준:** 앱이 Galaxy Tab에서 실행되고, 화면 회전·일시 중지·복귀가 정상이다.

### 2단계. 기본 UI·연령 선택·저장
- 홈, 과목 선택, 보호자 설정 화면을 만든다.
- 연령 프로필과 설정을 로컬 저장한다.
- 태블릿 화면 크기에 맞는 공통 버튼·텍스트·카드 스타일을 만든다.

**완료 기준:** 앱을 재실행해도 연령과 설정이 유지되고 주요 화면이 잘리지 않는다.

### 3단계. 따라 그리기 엔진
- 글자 하나, 알파벳 하나, 숫자 하나로 획 데이터 구조를 만든다.
- 시범 애니메이션, 점선, 터치 입력, 완료 판정, 힌트, 재시도를 구현한다.
- 획 판정은 단위 테스트 가능한 순수 Dart 로직으로 분리한다.

**완료 기준:** 테스트 케이스에서 정상 획·역방향 획·부분 획·화면 밖 터치·짧은 획이 의도대로 처리된다.

### 4단계. 자유 그림·작품 보관함
- 브러시, 색상, 지우개, 실행 취소, 저장·불러오기를 만든다.
- 작품 메타데이터와 이미지 파일을 연결한다.

**완료 기준:** 앱 재시작 후 작품을 열 수 있고, 삭제와 저장 실패가 안전하게 처리된다.

### 5단계. 한글·영어·수학 콘텐츠
- 처음에는 검수한 소량 콘텐츠만 제공한다.
- 오디오와 이미지 파일 ID를 연결한다.
- 연령별로 콘텐츠를 선택하고, 성공·실패에 따라 난이도를 조금씩 조정한다.

**완료 기준:** 글자 읽기, 알파벳 읽기, 수량·숫자 학습이 각각 처음부터 끝까지 가능하다.

### 6단계. 스토리 엔진과 에피소드 1
- 데이터 기반 장면 전환, 대사·오디오·효과음, 선택지, 퀴즈, 저장·이어하기를 구현한다.
- 《별빛 도서관과 사라진 이야기》의 1화 ‘빛을 잃은 도서관’을 완성한다.
- 정답, 오답, 힌트, 반복 실패 후 도움 통과를 테스트한다.

**완료 기준:** 이야기 시작부터 종료까지 이어지고, 앱을 닫았다 열어도 장면을 복구한다.

### 7단계. 시즌 1 콘텐츠 확장
- 2~12화의 장면과 학습 활동을 추가한다.
- 앞 에피소드의 학습 내용이 뒤 이야기에서 자연스럽게 다시 등장하는지 확인한다.
- 연령별로 장면 수·퀴즈 유형·판정 기준을 조정한다.

**완료 기준:** 12화가 하나의 연속된 이야기로 이어지고, 각 에피소드의 핵심 장면에 막힘 없는 도움 경로가 있다.

### 8단계. 보호자 기능·품질 개선
- 사용 시간, 음량, 도움 모드, 진도 초기화, 작품 관리 기능을 완성한다.
- 오프라인 실행, 메모리, 오디오 생명주기, 접근성, 태블릿 UI를 점검한다.

**완료 기준:** 핵심 학습 기능이 인터넷 없이 동작하고, 데이터 손상 없이 중단·재개할 수 있다.

### 9단계. 릴리스 APK
- 앱 이름·아이콘·패키지 ID·버전·서명 설정을 확정한다.
- 릴리스 APK를 빌드하고 Galaxy Tab에 새로 설치해 확인한다.
- 설치 방법과 테스트 결과, 알려진 제한사항을 README에 작성한다.

**완료 기준:** 개발 환경이 아닌 실제 태블릿에 릴리스 APK를 설치해 핵심 흐름을 재검증했다.

## 10. 에이전트 개발 규칙

코딩 에이전트는 다음 규칙을 지킨다.

1. 최초에 전체 개발 계획을 만들고, 각 단계의 목표·수정 파일·테스트·완료 기준을 `docs/PROGRESS.md`에 관리한다. 사용자의 단계별 승인을 기다리지 않고 진행한다.
2. 사용자가 요청하지 않은 서버·AI·로그인·광고 기능을 추가하지 않는다.
3. Flutter/Dart와 실제 Android 태블릿을 기준으로 설계한다. 웹 전용 기능에 의존하지 않는다.
4. 구현 전 최신 패키지 API와 Android 지원 범위를 확인하고, 존재하지 않는 API를 만들어 내지 않는다.
5. 기존 파일을 수정할 때는 파일 전체 구조와 호출 관계를 확인하고, 최소한의 범위로 바꾼다.
6. 코드만 제시하고 끝내지 말고 실행·테스트 명령과 성공 판단 기준을 제공한다.
7. 테스트를 실행하지 않았으면 통과했다고 말하지 않는다. 확인하지 못한 사항은 명시한다.
8. 글자 획·문제 정답·스토리 분기 데이터는 자동 생성 후에도 검수한다.
9. 모든 콘텐츠는 누락 리소스 검사 대상에 포함한다.
10. 각 단계가 끝나면 변경 파일, 구현된 기능, 실행 방법, 테스트 결과, 남은 문제를 `docs/PROGRESS.md`에 기록하고 다음 단계로 진행한다.
11. 첫 단계부터 시즌 1의 모든 그림·음성을 만들려 하지 않는다. 먼저 에피소드 1과 소량의 학습 항목으로 앱 구조를 검증한다.
12. 기능 구현보다 먼저 UI 장식이나 복잡한 게임 엔진 도입에 시간을 쓰지 않는다.

현재 작업 폴더의 docs/kkoma_spec.md를 전체 읽고, '꼬마 탐험 공부방' Flutter Android 앱을 명세서에 맞게 끝까지 개발해줘.

## 13. Windows 개발 환경 설정 (v1.1)

1. **Git** 설치: https://git-scm.com/downloads/win
2. **VS Code** 설치: https://code.visualstudio.com/ (Flutter, Dart, OpenAI Codex 확장 설치)
3. **Flutter stable SDK** 설치: https://docs.flutter.dev/get-started/install/windows/mobile — 영문 경로 예: `C:\src\flutter`, `PATH`에 `bin` 추가
4. **Android Studio** 설치: https://developer.android.com/studio — SDK Manager에서 Android SDK Platform, Build-Tools, Platform-Tools, Command-line Tools 설치
5. 터미널에서 `flutter doctor -v`, `flutter doctor --android-licenses` 실행. Android toolchain 문제 해결
6. Android Studio Device Manager에서 태블릿 AVD 생성, 호스트 CPU에 맞는 시스템 이미지 선택. Windows 가상화 기능 활성화
7. `flutter create --platforms=android kkoma_learning` 후 `cd kkoma_learning`, `code .`
8. `flutter devices`로 에뮬레이터 인식 확인 후 `flutter run`
9. VS Code에서 **OpenAI Codex** 확장을 설치하고 **ChatGPT 계정으로 로그인**. 프로젝트 루트에서 `docs/kkoma_spec.md`를 열어 11장의 프롬프트 실행
10. 개발 중 `flutter analyze`, `flutter test`; 배포 시 `flutter build apk --release`. APK 기본 경로는 `build/app/outputs/flutter-apk/app-release.apk`

참고: Windows 데스크톱용 Flutter 빌드는 이 프로젝트의 필수 요구사항이 아니다. 에뮬레이터 테스트만으로 실제 Galaxy Tab의 필기·음성·성능 검증을 대체하지 않는다.
